How every episode gets graded

There are essentially two independent reward channels, namely, Process (did the agent interact with all the required elements correctly) and Accuracy (was the clinical read correct), combined into one weighted grade per episode. Every point value below is the exact rule implemented in judge.py and grade_process.py.

Two-axis system

Process and Accuracy are scored, stored, and reasoned about independently, and a strong Accuracy score never offsets a broken workflow, and vice versa. Only at the very end are they combined into a single grade.

Process is fixed for every episode. Accuracy scales with how many real findings, diagnoses, and gold actions that specific visit has - attached below are the per-task tables.

Correction (this session): Process used to have its own "Action count calibration" check (old Z2.12) that penalized a missing gold action −5 and an extra one −0.25 - the exact same fact A3 already scores on the Accuracy axis (every missing gold action is independently a missed_by_model item there). The two axes are supposed to be independent reward channels, but for this one fact they weren't - the same miss was charged on both, giving action-set correctness roughly double the leverage of any single clinical-judgment error and making it possible to pass an episode on action selection alone with the entire written report missed. Z2.12 has been removed; A3 remains the sole place action-set correctness is scored, and Process's floor is back to a fixed constant since it no longer has an unbounded component.

Final grade formula

Raw point sums can't be weighted directly since Accuracy's scale (tens to hundreds of points) dwarfs Process's small range, so a naive 0.3×process + 0.7×accuracy wouldn't actually produce a 30/70 split. Both axes are normalized to [0,1] against their own ceiling/floor first, then weighted.

process_norm = (process_total − −12.5) / (12 − −12.5) accuracy_norm = (accuracy_total − floortask) / (ceilingtask − floortask) final_grade = 100 × ( 0.3 × process_norm + 0.7 × accuracy_norm )

The ceiling and floor only count real gold items , and anything the model made up (hallucinated) is left out, since a made-up item can only ever lose points, never earn extra credit toward the best-possible score. And whatever percentage comes out of the math is always kept between 0% and 100%, even in edge cases.

Total no-show special case

If the model does nothing at all, that is, it never logs in, never writes a note, every gold item shows up as "missed." Missing something now costs −5, the same magnitude as the match-status penalty on an actively wrong matched answer - but a badly- wrong matched item can still fall further, down to the −10 per-item floor, since its other quality fields (severity, location, reasoning, etc.) can also score negative on top of the match-status penalty. Left unchecked, silence could still be cheaper than trying and failing badly, so it's forced to 0% directly below rather than left to the normal math.

The no-show check reads the actual findings/impressions/follow-up strings straight from the episode log , were they empty before they were ever sent to the judge? If so, the score is forced straight to 0%, skipping the usual math. This is checked directly from the log rather than inferred from the judge's own output, since the judge is a separate LLM call and can occasionally misclassify an item on its own.

Presence absence
Did the model correctly say the finding is there vs. not there (this covers pertinent negatives like "no pneumothorax" too)?
Laterality
Left, right, or bilateral, was the side correctly identified?
Severity
How significant the finding is (mild vs. severe)
Location
How precisely the anatomical location was described.
Confidence Wording
Does the hedge language ("probable," "likely") match how certain gold actually is?
Clinical Reasoning
Does the reasoning connecting the finding to its significance actually hold up?
Comparison accuracy
When gold's finding is itself comparative ("unchanged," "increased since prior"), did the model correctly capture that same direction of change? Only scores when gold actually makes a comparison - ties directly to the new prior-studies timeline in the viewer (Z1.8).
Match status penalty
Was this finding addressed at all , and is it present, missed entirely, or made up? This is the field everything else in the row depends on: unless it comes back "matched," every other quality field is forced to zero, so match status alone decides whether the rest of the row gets to count at all. It's the single biggest lever on an item's score , since it guards against missed findings(false negatives) and hallucinations (false positives).

All fields 0 if not matched — match_status alone carries the miss/hallucination penalty, no double-counting across fields.

Per-task bounds

Process is fixed across every task (ceiling and floor both) - it no longer has any per-episode-scaling component now that Z2.12 is removed. Accuracy's ceiling and floor differ, scaled to each visit's real gold item count. The tables below predate several changes this session (Z1.8, comparison_accuracy, the −5/−5 match-status penalty, and the Z2.12 removal) and need a full numeric refresh - treat the per-task Ceiling/Floor columns as indicative, not exact, until that's done.
